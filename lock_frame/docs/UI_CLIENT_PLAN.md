# lock_frame 可视化客户端：易用性分析与改造方案

> 目标：**lock_frame 研发结束，功能不再是瓶颈；让没用过命令行、不懂 DXGI/WGC/配对的人
> 也能在 3 步内跑起来**。本文是代码级现状分析 + 改造规格 + 落地状态。
>
> 结论先行：**不需要重写渲染层**。现有 `ui/mgpu_ui.cpp` 已经是一套自绘 Win32 深色 UI
> （1200×620、卡片式布局、下拉/开关/数字框全部自绘），它缺的不是"更好看的皮肤"，而是
> **一条从 0 到跑通的主干流程**。方案是在同一份代码里加一层"简易模式"（默认），
> 把原有卡片整体降级为"高级模式"。

## 1. 现状盘点（代码级证据）

| 能力 | 现状 | 位置 |
|---|---|---|
| 选游戏窗口 | 枚举 ≥1280×720 的可见顶层窗口，按面积排序，按标题记忆 | `enum_win_proc` / `rescan_windows` |
| 启动消费端 | `CreateProcess` + 管道抓 stdout，参数由 `build_cmdline` 拼 | `start_bridge` / `build_cmdline` |
| 全局热键 | 9 个预设 + 自定义组合键 + 轮询型兜底（CapsLock+PageUp） | `apply_hotkey` / `hotkey_poll_thread` |
| 环境自检 | 只数 GPU 数量、看两个 DLL 在不在、读 `fakerFG.ini` 三个键 | `row_value: ID_CHECK_*` |
| 游戏侧配置 | 只改**已存在**的 `fakerFG.ini` 的 `FgInput`，写前备份 | `apply_fg_input` |
| 部署 | **不在 UI 里**，靠 `deploy_game.bat "游戏目录"` 命令行 | `deploy_game.bat` |
| 诊断 | **不在 UI 里**，靠 `collect_diagnostics.bat` | `collect_diagnostics.bat` |
| 运行状态 | 底栏一行 `show/xN/skip/gpu/game ms` + 最近一条 WARNING | `parse_line` / `paint` |
| 错误提示 | 一行中文，底栏右侧 `DT_END_ELLIPSIS` 640px 内截断 | `set_msg` / `paint` |
| 参数暴露面 | 7 张卡片、23 行，其中 11 行是 A/B 或实验开关 | `kCards` |

**判断**：技术上"能做的都做了"，但**产品上每件事都要求用户先懂它**。这正是小白卡住的原因。

## 2. 小白真实旅程里的 12 个断点

按时间顺序，全部来自现有代码的行为，不是猜测。

| # | 阶段 | 用户看到什么 | 断点 | 现在的代码行为 |
|---|---|---|---|---|
| 1 | 拿到压缩包 | 一个目录，20+ 文件 | 不知道哪些要复制、复制到哪 | README 写"运行 `deploy_game.bat "目录"`" |
| 2 | 找游戏目录 | 要手打 exe 路径 | 不懂"exe 所在目录"与 steam 库结构 | 只有 `.bat` 参数 |
| 3 | 自备运行时 | 需要 `libxess_fg.dll` / `libxell.dll` | 不知道版本要求（1.3.1.78 / 1.3.2.10） | UI 只检查"文件在不在" |
| 4 | 启动游戏 | 需要开 DLSS 帧生成 | 不知道"必须开 FG、必须无边框全屏" | UI 不检查，只在启动失败后提示 |
| 5 | 打开 UI | 7 张卡片、一堆英文缩写 | 认知过载，不知道从哪点 | 全部平铺，无主次 |
| 6 | 选窗口 | 列表里有浏览器/桌面 | 不知道要选"游戏"，且 1280×720 以下不出现 | 下拉框 |
| 7 | 选倍率 | `2x（输入 60.0 fps → 输出 120 fps）` | 不知道选哪个、不知道要回去锁帧 | 只有文案，无强制/引导 |
| 8 | 游戏内锁帧 | UI 显示"建议锁帧 40 fps" | 不知道 RTSS / 游戏设置怎么锁 | 只显示文字 |
| 9 | 点启动 | 底栏一行"已启动" | 失败时也只有一行字，且被截断 | `set_msg` |
| 10 | 画面没变化 | 底栏 `show 118` 但看不出是否在插帧 | 没有"成功/降级/失败"结论 | 只有原始计数 |
| 11 | 出问题 | 需要日志 | 不知道日志在哪、怎么发给人 | 日志在 exe 旁边，UI 无入口 |
| 12 | 想撤销 | `dxgi.dll` 已被替换 | 不会还原，怕搞坏游戏 | 只有 `.bak`，UI 无还原 |

**共性**：12 个断点里，**9 个是"缺一步自动化"，2 个是"缺一句人话"，1 个是"缺一个撤销"**。
没有一个是必须改内核才能解决的。

## 3. 设计原则

1. **默认简易，进阶才展开**：打开就是"准备状态 + 3 步"，高级卡片一键折叠。
2. **每个状态都要有颜色 + 一句话 + 一个按钮**：不允许"只显示一个数值/一行日志"。
3. **所有破坏性操作都可逆**：部署自动备份；UI 提供还原；还原前后都有明确文案。
4. **失败必须给"下一步"**：错误卡片 = 现象 + 原因 + 动作按钮（不是日志行）。
5. **不新增需要联网/上传的东西**：诊断包本地生成，符合现有 `collect_diagnostics.bat` 的定位。
6. **不自造第二套状态**：就绪判定复用已有函数（`exe_file_exists`、`target_game_ini`、
   `target_is_producer`、共享内存协议版本），避免 UI 说 OK 但 consumer 说不 OK。

## 4. 信息架构：游戏为中心（2026-11-19 二次改版）

```text
┌ 标题栏：MGPU 双显卡帧生成                          [－] [✕]
├──────────┬───────────────────────────────────────────────┐
│ 游戏列表 │  当前游戏（配置属于这个游戏）                 │
│ ● MixGame│   名称 / 路径 / 2x · 输入 60fps · DLSSG · MV150 │
│ ○ Auto   │   [游戏侧安装][运行时][fakerFG.ini][producer]  │
│          │   [选择游戏…][安装/应用配置][还原/移除组件]    │
│ + 选择/  │  启动补帧                                     │
│   添加…  │   [窗口 ▾][刷新]                              │
│          │   [2x][3x][4x]                  [启动补帧]     │
│ 帮助(F1) │   就绪提示：缺什么 / 一切就绪可以启动          │
│ 高级设置 │  运行状态：徽章 · 数据 · 日志行                │
└──────────┴───────────────────────────────────────────────┘
```

- **一个游戏 = 一份完整配置**（2x/3x/4x、FgInput、MV 比例、Log、输出模式、GPU、
  热键、OSD…）。每份配置写在 `profiles\<游戏名>.ini`，`lock_frame_ui.ini` 只存索引
  （`[games] count` + 每项 `path/name`）；切游戏 = 切配置，改动立刻落盘。
- 第一步是**选游戏**：唯一入口是「当前游戏」卡片标题右侧的强调色按钮
  （未选=「选择游戏」，已选=「更换游戏」）；侧栏列表用于快速切换。
- **游戏库 = 选择器**：只做"添加 exe… / 点一行选中"（全局扫描默认不暴露，见 §8.3），不安装、不删除；
  安装与还原在「当前游戏」卡片里，主程序改在卡片右下角「主程序…」。
- **安装 = 应用配置**：部署组件的同时把该游戏的配置写进它的 `fakerFG.ini`；
  「还原 / 移除组件」与安装互斥（未安装时置灰），还原后回到"未安装"状态。
- 「启动补帧」卡片只做三件事：显示该游戏窗口是否找到、选倍率、启动。就绪条件
  （安装 + 窗口 + producer + 运行时）不满足时按钮置灰并给出唯一的下一步文案。
- **高级设置只有一个入口**：与「安装 / 还原」同一行、右对齐（`高级设置` → `主程序…`），
  次级按钮样式 + 左侧强调条；点开后右侧抽屉覆盖该行（安装/还原不可点），
  抽屉里只显示"正在编辑：<游戏>"和「完成」；打开游戏库/日志/帮助会自动收起抽屉。
- **栅格**：侧栏 232、外边距 20、标题栏 42；三块卡片 94–308 / 322–528 / 542–700，
  间距 14，内边距 18；一屏只有一个主色按钮组（更换游戏 / 安装 / 启动）。
- 旧的"①②③ 三步卡片"和"游戏配置（profile）列表"已移除，避免两套概念并存。

## 5. 就绪状态模型

`refresh_readiness()`（新）每 2 s 重算一次，供简易模式与启动前检查共用：

| 项 | 判定 | 失败文案 |
|---|---|---|
| `deployed` | 选定游戏目录里 `fakerFG.dll` + `dxgi.dll` 同时存在 | "游戏侧还没有装锁帧组件" |
| `runtime` | `lock_frame_ui.exe` 同目录有 `libxess_fg.dll`；3x/4x 还需要 `libxell.dll` | "缺少 Intel 运行时（正式包默认不内置）" |
| `window` | 下拉选中的窗口仍存在（`IsWindow`） | "请先进入游戏画面再刷新窗口列表" |
| `producer` | 选中窗口的进程模块里有 `xess_mfg_producer.dll`（`TH32CS_SNAPMODULE`） | "游戏还没加载 producer：确认已开 DLSS 帧生成" |
| `ini` | 游戏目录 `fakerFG.ini`：`FgOutput=Capture`、`Passthrough=0`、`FgInput` 非空 | "fakerFG.ini 不是消费者链路配置" |
| `gpus` | DXGI 枚举到 ≥2 块非软件适配器 | "只检测到 1 块 GPU：能跑，但不建议" |
| `divisible` | `面板刷新率 % 倍率 == 0` | "165 Hz ÷ 4 不整除，节奏不会完美" |

`producer` 是**新增的强信号**：它比"共享内存存在"更早（窗口刚出现就能判断），
也解释了 `target_is_producer` 失败时到底是"没装"还是"没进画面"。

## 6. 一键部署 / 还原规格（替代 `deploy_game.bat`）

`deploy_game_dir(dir)`，幂等：

1. 校验源文件：`<exe 目录>\fakerFG.dll` 必须存在，否则直接报错（不半装）。
2. `dxgi.dll` 备份：仅当 `dxgi.dll` 存在、`fakerFG.dll` 不存在、`dxgi.dll.bak` 不存在时
   重命名为 `dxgi.dll.bak`（重复部署不会把我们的 DLL 备份成 .bak）。
3. `nvngx_dlssg.dll` → `nvngx_dlssg_real.dll`：仅当反向文件不存在时执行一次。
4. 复制 `fakerFG.dll` 三处：`dxgi.dll`、`nvngx_dlssg.dll`、`fakerFG.dll`。
5. `xess_mfg_producer.dll` 存在就复制。
6. `fakerFG.ini` **只在缺失时**放模板（绝不覆盖用户配置）。
7. 冲突提示：目录里有 `version.dll`（dlssg_sm86）时明确警告。
8. 结果用 `MessageBoxW` 明文列出每一步，成功/失败都可见。

`undeploy_game_dir(dir)`：

1. 只有检测到"确实是我们装的"（`fakerFG.dll` 存在）才继续，否则提示无事可做。
2. 删除 `dxgi.dll` / `nvngx_dlssg.dll` / `fakerFG.dll` / `xess_mfg_producer.dll`。
3. `dxgi.dll.bak` → `dxgi.dll`；`nvngx_dlssg_real.dll` → `nvngx_dlssg.dll`。
4. 保留 `fakerFG.ini`（用户配置），并在结果里说明。

游戏目录来源：`GetOpenFileNameW` 让用户**选游戏 exe**（比让用户手打目录可靠得多），
取父目录；路径写进 ini（`[ui] game_dir`），下次直接用。

## 7. 启动前检查（preflight）

`start_bridge()` 在拿到目标窗口后、`CreateProcess` 之前执行；只在**用户主动点启动**时弹窗
（热键启动不弹，避免游戏里被打断）。

按严重度分三档：

| 档 | 条件 | 行为 |
|---|---|---|
| 阻断 | 没有目标窗口 / 找不到 `lock_frame.exe` / 协议版本不符 | 弹错误卡（已有逻辑，改成文案化） |
| 警告（可继续） | 单卡、缺 `libxell`（3x/4x）、`fakerFG.ini` 不是 Capture、面板不整除、没检测到 producer 模块 | `MB_YESNO`「仍然启动？」并列出全部原因 |
| 提示 | 输入帧率远低于 `面板/倍率` | 启动后状态卡提示"输入 52 fps，建议锁 40" |

## 8. 运行期"人话"状态

从 `[lock] pair: exact=40 no_slot=0 ... (total=40)` 提取 `exact/total`，映射成结论：

| 条件 | 徽章 | 一句话 | 建议动作 |
|---|---|---|---|
| 未运行 | 灰 · 未运行 | 点「启动」开始 | — |
| 运行中，`exact/total ≥ 0.9` | 绿 · 插帧中 | 正在补帧（40/40 命中） | 按热键停止 |
| 运行中，`0.5 ≤ 命中 < 0.9` | 黄 · 部分插帧 | 部分帧没配上（32/40） | 看卡顿 / 关 HUD 遮挡四角 |
| 运行中，`命中 < 0.5` | 红 · 几乎没插帧 | 配对失败，输出接近原生 | 一键诊断 |
| 运行中，`show ≈ 面板` 但 `xN < 1.5` | 黄 · 节奏异常 | 输入不在建议帧率 | 游戏内锁 `面板/倍率` |

同时把 `g_last_line`（WARNING/ERR）作为状态卡第二行**完整显示**（可换行，不截断）。

## 9. 高级模式降噪

高级模式保持原布局，只做三件事：

1. **A/B 行保持现有 `(A/B)` 后缀**，卡片标题不额外加噪；
2. **启动命令默认折叠**：只占一行，右侧「展开 ▾ / 收起 ▴」，状态写 `[ui] show_cmd`；
3. 简易模式状态卡里提供 `一键诊断` / `打开日志目录` / `查看日志` 三个入口；
   高级模式保持原布局（完整日志仍写在 exe 旁边）。

## 8.1 内嵌日志查看器

- 保留最近 **400 行**：consumer stdout（`reader_thread` 每条完整行）+ UI 自己的
  `[ui] …` 消息，统一进 `g_log_lines`（`g_line_cs` 保护，UI 线程只读快照）。
- 面板是模态覆盖层：整窗压暗 + 面板，标题「运行日志（最近 400 行）」，
  右上「刷新 / 关闭」；列表用 Consolas 等宽字体，`WARNING` / `ERR` / `失败` 变黄。
- 翻页：滚轮（3 行/格）、PageUp / PageDown（一页）、Home / End、Esc 关闭。
- 打开时取快照，运行中的新行不会让正在看的列表跳动；点「刷新」重新取。
- 完整日志仍然写在 exe 旁边的 `lock_frame_ui_HHMMSS.txt`（保留 8 份）。

## 8.2 游戏库与首次运行欢迎页

**游戏库**（`lock_frame_ui.ini` 的 `[games]` 索引 + `profiles\*.ini` 单游戏配置）：

| 字段 | 说明 |
|---|---|
| `dir` | 已解析的部署目录（游戏 exe 所在，唯一键之一） |
| `root` | 安装根目录（扫描得到；没有 `dir` 时用它做索引） |
| `name` | 显示名（Steam 用清单里的 name，其余用目录名） |
| `source` | Steam / Epic / GOG / 注册表 / 手动 |
| `mult` / `fg_input` / `lock` | 上次使用的倍率 / 输入源 / 建议锁帧 |

**本机扫描**（代码保留，默认不在 UI 暴露：筛选规则还不够可靠，先只用「添加 exe…」）：

| 来源 | 位置 |
|---|---|
| Steam | `HKCU\Software\Valve\Steam\SteamPath` + `steamapps\libraryfolders.vdf` + `appmanifest_*.acf` |
| Epic | `%ProgramData%\Epic\UnrealEngineLauncher\LauncherInstalled.dat` |
| GOG | `HKLM\SOFTWARE\WOW6432Node\GOG.com\Games\*`（gameName / path） |
| 通用 | 三条 Uninstall 注册表路径的 `DisplayName` + `InstallLocation` |

- 过滤：运行库 / Redistributable / SDK / DirectX / Steamworks / Proton / SteamVR /
  EasyAntiCheat / BattlEye / Dedicated Server；跳过 WindowsApps 与 `%WINDIR%`。
- 索引与去重：`dir` 优先、`root` 次之，路径统一小写去尾斜杠比较；最多 200 条。
- 选中条目点「使用此游戏」：能用 `dir` 就用；只有 `root` 时向下 3 层找"最大且不像
  卸载/崩溃/启动器"的 exe，取其目录作为部署目录；都不行再用 `[手动 exe]` 指定。
- 面板里直接提供「安装 / 更新」「还原」「删除」；删除只删记录，不动文件。
- 写入时机：安装成功、成功启动、在抽屉里改 fakerFG 输入源；读取：启动 UI、
  选中游戏窗口、从游戏库切换。最近使用时间排序。

**首次运行欢迎页**：`[ui] welcomed=0` 时启动后显示一次，三条要点
（双卡 / 游戏要开 FG 且无边框 / 三步走）+「知道了，开始」；点按钮、Enter、Space、
Esc 都可关闭，随后 `welcomed=1` 不再出现。

## 8.3 悬浮说明与去重

- **悬浮说明**：鼠标停在按钮/选项行 450 ms 后，在光标旁弹出说明框（自动避让窗口
  边界，最多 300 px 宽、自动换行）。覆盖：三步流程的全部按钮、抽屉里的全部选项行
  （日志/游戏库面板是模态层，暂不做说明框）。
- **键盘（2026-11-19 补全）**：抽屉内 `Tab / Shift+Tab` 或 `↑ / ↓` 移动焦点（蓝色
  焦点环，自动滚到可见位置），`Enter / Space` 激活当前项（开关、数字 +1、打开下拉、

## 8.5 UIA 可访问性（讲述人 / NVDA）

`WM_GETOBJECT` 返回自定义 UIA provider（`UiaReturnRawElementProvider`），暴露：

| 元素 | ControlType | AutomationId |
|---|---|---|
| 窗口 | Window | `root` |
| 安装 / 还原 / 游戏库 / 选窗口 / 刷新 | Button | `install` / `undeploy` / `gamelib` / `window` / `refresh` |
| 2x / 3x / 4x / 启动·停止 | Button | `2x` / `3x` / `4x` / `start` |
| 查看日志 / 一键诊断 | Button | `logview` / `diag` |
| 帮助 / 高级设置 | Button | `help` / `advanced` |
| 运行状态（徽章 + 建议） | Text | `status` |

- **Invoke 模式**：读屏器"按下"按钮 → `PostMessage(WM_APP+2, id)`，在 UI 线程执行与鼠标相同的动作。
- **焦点**：`SetFocus` / Tab 改变焦点时调用 `UiaRaiseAutomationEvent(UIA_AutomationFocusChangedEventId)` 并补 MSAA `EVENT_OBJECT_FOCUS`；`GetFocus` / `ElementProviderFromPoint` 支持读屏器查询当前焦点与鼠标命中的元素。
- **边界矩形**：按 DPI 映射到屏幕坐标（`uia_to_screen`）。
- **抽屉/日志/游戏库/欢迎页**：模态期间子元素 `IsOffscreen=true`、`IsEnabled=false`，收起后恢复。
- 线程模型：`ProviderOptions_ServerSideProvider`（调用在 UI 线程）；provider 为进程级单例、不 delete，避免 UIA 异步回调悬空。

**已验证**（PowerShell + `UIAutomationClient`）：枚举到窗口 + 13 个 Button + 1 个 Text（名称/类型正确）；
对 `AutomationId=logview` 调用 `InvokePattern.Invoke()` 成功打开了日志面板。
**待你本机用讲述人 / NVDA 复核朗读顺序与措辞。**

## 8.7 游戏侧 fakerFG.ini 参数（必要项）

UI 只暴露**影响双卡链路的三项**，其余键保持不动；每个游戏目录的 `fakerFG.ini`
各自独立，互不影响：

| UI 项 | ini 键 | 值 |
|---|---|---|
| fakerFG 输入源 | `FgInput` | DLSSG / NVNGX / Upscaler / FSR |
| MV/深度传输比例 | `StreamPercent` + `StreamPercentMv` + `StreamPercentDepth` | 100%（1:1）/ 150%（默认，每维 2/3）/ 200%（每维 1/2）/ 400%（每维 1/4） |
| 游戏侧日志 | `Log` | 1 / 0 |

**写入时同时固定**（双卡消费者链路要求，不暴露给用户）：
`FgOutput=Capture`、`Passthrough=0`、`RealSwapchainObject=1`。

行为：

- **按游戏独立**：路径优先 `g_game_dir`（游戏库选中的目录），否则取当前游戏窗口的
  exe 目录；不会写到别的游戏。
- **逐次备份**：每次写入前复制为 `fakerFG.ini.bak_<tick>`，每个游戏目录只保留最新
  **8 份**（`prune_ini_backups`）；删除游戏/还原部署都不动这些备份。
- **读回**：启动 UI、选中游戏窗口、从游戏库切换、自动发现游戏时，都会读回
  `FgInput / StreamPercent(Mv) / Log`，保证界面显示的是这个游戏真实生效的值。
- **必须重启游戏**：producer 每个会话只读一次 `fakerFG.ini`；UI 写入后会提示
  "重启游戏生效"。
- 自定义的 `StreamPercentMv/Depth` 若不是四档之一，界面显示最接近的一档；一旦在 UI
  里修改，会把三个键统一写成所选值。

## 8.8 主程序自动解析（用户不需要知道 exe）

游戏包体里常有多个 exe（启动器、崩溃报告、反作弊、真正的主程序），位置也各不相同。
UI 在**选中游戏条目**或**点安装**时自动解析主程序，用户只需要「安装 / 还原」。

**打分规则**（`resolve_game_exe`）：

| 信号 | 分值 |
|---|---|
| PE 导入表含 `d3d11.dll` / `d3d12.dll` / `dxgi.dll`（直接读导入表，不运行） | +60 |
| 文件名含 `shipping`（UE 的 `-Win64-Shipping.exe`） | +25 |
| 文件名含 `game` | +15 |
| 名字与游戏目录相似（完全/包含/≥4 字符前缀） | +30 / +20 / +10 |
| 体积 ≥20 MB / ≥8 MB / ≥1 MB | +25 / +15 / +5 |
| 目录深度 0 / 1 / 2+ | +10 / +6 / +3 |
| 明确黑名单（unins/setup/redist/crash/report/launcher/helper/anticheat…） | 直接跳过 |
| < 1 MB、`redist`/`_CommonRedist`/`DirectX`/`Engine`/反作弊目录 | 直接跳过 |

- 最高分 ≥ 40 才采纳；否则不猜，提示「主程序待解析」，由「自选 exe…」手动指定。
- 解析结果写入该游戏的 `profiles\*.ini`（`exe=` / `dir=`）；游戏库行直接显示
  「主程序：Game-Win64-Shipping.exe」。
- **已安装检测**：`find_deployed_dir` 在游戏根目录 3 层内找 `fakerFG.dll`，命中就把
  `dir` 定为该目录（已部署的游戏无需再猜 exe）。
- **自选 exe…（高级）**：游戏库右上角按钮 → 选 exe → 生成/更新该游戏条目
  （`dir`/`exe`/`root`）→ 立即询问是否安装。原来只想加条目的"手动 exe"已改为
  "自选 exe 安装…"，一键完成配置 + 安装。
- **主程序…（候选面板）**：不确定或想换主程序时，按分数列出该目录内最多 8 个候选
  （文件名 / 体积 / 分数 / 完整路径），点一行即写入 `exe=`/`dir=`；面板高度随候选数
  自适应，点面板外或 Esc 关闭。安装时若目录还没解析出主程序，会先弹这个面板，
  选完自动继续安装（不再直接掉进文件选择框）。
- **后台初始化**：扫描或启动后，未解析的条目每 4 s 解析一个（轮询、不阻塞 UI），
  解析成功即落盘并刷新行内文字；扫描完成后从新条目开始优先解析。
- 安装成功后会再次解析一次 exe（保证 `exe=` 落盘），之后「使用此游戏 / 还原 / 删除」
  都基于这个目录。

27. 抽屉「游戏侧配置」改 MV/深度比例为 200%、关掉游戏侧日志 → 该游戏的
    `fakerFG.ini` 出现 `StreamPercent/Mv/Depth=200`、`Log=0`、`RealSwapchainObject=1`，
    并生成 `fakerFG.ini.bak_<tick>`（每个游戏目录最多 8 份）。
28. 重启 UI → 两个控件显示 200% 与关闭（读回的是这个游戏目录的真实值）。
29. 含多个 exe 的游戏（如 `Game.exe` + `Launcher.exe` + `bin/Win64/Game-Win64-Shipping.exe`）：
    在游戏库里点中它 → 行内显示"主程序：Game-Win64-Shipping.exe"，
    `profiles\*.ini` 的 exe/dir 自动落盘；点「安装 / 更新」直接部署到该目录，无需选 exe。
30. 已部署过的游戏（目录里有 fakerFG.dll）→ 选中即识别为"已安装"，
    路径指向实际部署目录。
31. 点「自选 exe…」→ 选择任意 exe → 生成/更新该游戏条目并询问安装；
    安装完成后条目里 `dir/exe` 正确。
