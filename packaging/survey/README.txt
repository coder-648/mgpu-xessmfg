===============================================================================
 mgpu 采集探针  ——  多游戏 FG 数据可得性调查包
===============================================================================

一、这是什么
-------------------------------------------------------------------------------
在【不改游戏文件、不装 ReShade】的前提下，把游戏帧生成真正用到的数据
（MV / depth / HUDless 颜色 / UI / 相机矩阵）在它们被消费的那一刻抓下来，
写一份日志说明「这个游戏到底提供了什么」。

这一版只做「采集 + 记录」：不生成插值帧，也不改动游戏自己的帧生成设置。
目的：确认这套获取方式在不同引擎、不同游戏上是不是一致的。

二、怎么装（每个游戏各做一次）
-------------------------------------------------------------------------------
1) 找到游戏主 exe 所在目录（不是游戏根目录），常见形如
       <游戏>\bin\x64\          或  <游戏>\
2) 把这四个文件放进去（其余留作参考，不必拷）：
       version.dll
       mgpu_capture.dll
       mgpu_capture.ini
       mgpu_proxy.ini
3) 启动游戏，正常玩 30~60 秒（最好进一次菜单、换一次场景或载具）。
4) 退出游戏。目录里会出现：
       mgpu_proxy.log     代理/宿主是否起来的证据
       mgpu_capture.log   采集核心日志（关键）
5) 双击 collect_logs.bat，把生成的 zip 发回。

注意：
  * 只支持 D3D12 游戏。DX11 / Vulkan / OpenGL 游戏只会看到 proxy 日志、没有采集，
    这本身也是有用的结论。
  * 带反作弊的游戏请勿使用（会被判定为注入）。
  * version.dll 与 mgpu_capture.dll 必须成对更新，不要混用旧版本。
  * 想关掉：删掉这四个文件即可；游戏目录里没有别的东西被改动。

三、日志里我们要看的行
-------------------------------------------------------------------------------
1) 宿主/核心是否起来
     mgpu_proxy.log   : host: mgpu_capture.dll loaded (...)
     mgpu_capture.log : === game_capture ... build ...

2) 数据来源是否被识别（本次调查的核心）
     harvest: mv=y depth=y camera=y clip=y token=? reset=? hudless=? ui=? scaling=i?
       —— 每一项 y/n 就是该游戏在这一帧是否提供了该数据
     semantics: mv=<单位> sign=<方向> camera=<来源> depth=<能否用> valid=WxH

3) 具体 tag 集合（Streamline 游戏）
     fg: sl.tags #N 之下若干行，形如
        SEQUENCE_ID   ( 47) ...
        SCALING_INPUT (  3) ... extent=(0,0 3840x2160) state=0x8 lc=1(validUntilPresent)
       —— 看得出该游戏 tag 了哪些资源、状态与生命周期声明

4) 输送情况（实测字节数，不是配置值）
     streams: ... one copy: colour=? mv=? depth=? ui=? MB | total ?.?? MB/frame
     pending: N calls, P parked, C copied, skip(slot=? state=? fmt=?)

5) 被跳过的原因（一并回传，别靠猜）
     [mv] / [depth] skipped: ... format ... does not match the slot
     fg: record skipped (...) - shared=0 / no free slot

四、这一版的已知行为
-------------------------------------------------------------------------------
* mv/depth 默认按 1/2 传输（StreamPercent=200）：4K 每条流约 7.9 MB。
  实测成本约为「字节数 / 13 GB/s」，即每条 31.6 MB 的满尺寸流 ≈ 2 fps。
* Color=1 / Ui=1 这一版是开着的，为了调查游戏到底有没有给 HUDless/UI。
  若某个游戏颜色格式不匹配，日志会写 format ... does not match the slot，
  这本身就是我们要的信息——请原样发回。
* FgCut=0：不切断游戏自己的帧生成，保证看到的是真实场景。
* 所有配置项在 mgpu_capture.ini 里逐条中文说明；改完需要重启游戏才生效。

五、回报时最有用的三样
-------------------------------------------------------------------------------
1) collect_logs.bat 生成的 zip（两份日志 + 当时的 ini）
2) 游戏名 / 引擎 / 图形 API / 分辨率与 DLSS 或 FSR 档位
3) 一句话：该游戏自己开帧生成时画面是否正常、帧率大概多少
